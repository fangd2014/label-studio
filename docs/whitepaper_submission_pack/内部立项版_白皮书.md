# 1. 立项背景与必要性

当前公司多个 AI 项目在数据环节存在重复建设与质量波动问题，导致整体交付效率不稳定、算法团队返工成本高、业务上线周期拉长。各业务线采用不同标注流程和工具，无法形成统一的数据资产管理体系。

立项建设 Label Studio 平台的必要性：
1. 统一流程：消除多团队重复建设，建立可复用规范。  
2. 提升效率：通过模板化与人机协同提升整体产能。  
3. 稳定质量：通过审核与一致性机制降低质量波动。  
4. 支撑治理：满足审计追踪、安全合规与数据留存要求。  
5. 降低成本：减少返工与管理复杂度，提升投入产出比。

# 2. 项目目标与范围

## 2.1 项目目标

1. 建成统一多模态标注平台。  
2. 建成公司级标注规范与质量标准。  
3. 打通“标注—训练—评估—回流”数据闭环。  
4. 建立安全与审计可追溯机制。  
5. 支持跨业务线复制与规模化运营。

## 2.2 项目范围

1. 平台能力：项目管理、任务流转、标注执行、审核复核。  
2. 集成能力：数据源、模型服务、训练平台、导出接口。  
3. 治理能力：权限体系、审计日志、数据策略。  
4. 运营能力：质量看板、效率看板、版本管理。

## 2.3 范围外项（当前阶段）

1. 与项目目标无直接关系的历史系统全面替换。  
2. 非优先业务线的深度个性化定制。  
3. 与核心 KPI 无关的装饰性功能开发。

# 6. 实施计划与里程碑

## 6.1 阶段规划（12 个月）

2. 阶段 II（4-6 个月）：质量管理与预标注能力接入。  
3. 阶段 III（7-9 个月）：多业务线复制与治理标准化。  
4. 阶段 IV（10-12 个月）：运营固化与规模化推广。

## 6.2 关键里程碑

1. M1：完成架构评审与需求冻结。  
2. M2：完成试点上线并形成首轮 KPI 数据。  
3. M3：完成跨业务线复制并通过安全审计。  
4. M4：完成公司级平台化验收。

# 7. KPI 与验收标准

## 7.1 效率 KPI

1. 单位样本标注时长下降 ≥30%。  
2. 训练数据交付周期缩短 ≥40%。

## 7.2 质量 KPI

1. 首次通过率提升 ≥20%。  
2. 返工率下降 ≥25%。  
3. 一致性指标稳定在目标阈值以上。

## 7.3 治理 KPI

1. 关键操作审计覆盖率 100%。  
2. 权限合规检查通过率 100%。  
3. 安全策略执行偏差率持续下降。

## 7.4 验收标准

1. 达成核心 KPI。  
2. 完成试点与扩容场景验收。  
3. 输出可复用流程规范与运维手册。  
4. 通过安全与合规评审。

# 8. 风险评估与应对预案

1. 需求膨胀风险：实施阶段严格范围管理，优先核心 KPI。  
2. 协同效率风险：建立责任矩阵与固定节奏评审。  
3. 质量标准不统一风险：建立样本标准库与审核准则。  
4. 上线 adoption 风险：通过试点成果驱动组织推广。  
5. 合规风险：前置介入安全与法务评估，分阶段放量。

# 10. 统一术语页

| 术语 | 定义 | 在内部治理中的意义 |
|---|---|---|
| 数据标注 | 对样本内容进行结构化语义标记 | 训练与评估数据标准入口 |
| 标注规范 | 标注执行与审核的统一规则 | 跨团队质量一致性的基础 |
| 预标注 | 模型先生成初始标注建议 | 提升人效并缩短周期 |
| 主动学习 | 优先处理高价值/高不确定样本 | 提升单位投入产出比 |
| 一致性指标 | 多人对同样本标注一致程度 | 衡量标准稳定与培训效果 |
| 返工率 | 被审核驳回需重做的比例 | 衡量流程成熟度 |
| 数据闭环 | 标注结果回流模型驱动迭代 | 形成持续优化机制 |
| 审计日志 | 关键行为留痕记录 | 支撑合规与责任界定 |
| RACI | 责任分配模型（负责/审批/协作/知会） | 保证跨团队执行效率 |
| SLA | 服务级别承诺 | 保障交付与支持质量 |

# 11. 附录 A：指标口径

## A.1 项目效率指标

1. 平均标注时长 = 总标注时长 / 标注样本数。  
2. 单人日产能 = 日产出样本 / 人天投入。  
3. 交付周期 = 任务创建至业务验收时长。

## A.2 质量指标

1. 首次通过率 = 一次审核通过样本 / 审核总样本。  
2. 返工率 = 驳回样本 / 标注总样本。  
3. 一致性得分 = 双盲样本一致数 / 双盲样本总数。

## A.3 治理指标

1. 审计覆盖率 = 有审计记录关键操作 / 关键操作总数。  
2. 权限合规率 = 符合最小权限策略账号 / 账号总数。  
3. 变更及时率 = 在 SLA 内完成的需求变更 / 总变更数。

# 12. 附录 B：实施清单

## B.1 立项前清单

1. 明确业务目标、范围与边界。  
2. 明确牵头部门与负责人。  
3. 明确预算上限与资源投入方式。  
4. 完成立项评审材料与风险披露。

## B.2 执行期清单

1. 需求冻结与版本规划是否完成。  
2. 试点范围与验收标准是否锁定。  
3. 安全合规评审是否按阶段完成。  
4. KPI 报表是否按周/月稳定输出。

## B.3 验收期清单

1. 核心 KPI 是否达标。  
2. 文档与操作手册是否齐备。  
3. 组织培训与交接是否完成。  
4. 后续优化路线与责任人是否明确。
